# dsh-oc perf：0.2.0-rc.4 / dsh 0.1.5-rc.2（2026-09-11）

环境与口径沿用 [results-2026-08-15.md](results-2026-08-15.md)：真实 dsh
profile + fake opencode 子进程、合成 5000 会话、冷/热读分别取样。rc.4 的主要
新工作是把 0.1.5 内嵌 `assistant/message.stream` 展开成历史行，以及给流式中的
history 合并 live provisional assistant；两者都在 history 转换路径上，故重点
复核列表与消息读。

命令：`pnpm run perf -- --sessions 5000`（report：
`.perf/report-1789067463861.json`，本机产物不入库）。

| 指标 | rc.4（dsh 0.1.5-rc.2） | rc.3 基线（dsh 0.1.2） |
|---|---|---|
| `GET /session`（v1 list）p50 / p95 | 33ms / 1600ms | ~20ms / ~1360ms |
| `GET /api/session`（v2 list）p50 / p95 | 7.6ms / 10.0ms | ~2ms / ~75ms |
| `GET /session/:id/message` p50 / p95 | 13.0ms / 24.5ms | ~1.3–1.8s 冷读 / — |
| `GET /api/session/:id/message` p50 / p95 | 5.4ms / 9.0ms | ~1ms / ~2.4ms |
| `GET /api/session/:id/history` p50 / p95 | 3.3ms / 8.3ms | ~1.0ms / ~1.4ms（热） |
| 分页 history（1 页 / 6 消息） | 3.0ms | — |
| 启动 / RSS | 3.0s / 373MB | — |

结论：

- v2 列表 p95 从 ~75ms 降到 10ms 以内；v1 冷列表 p95 1.6s 与 0.1.5 上游
  `session.list` 扫描量一致（会话数 + 标题补温），没有出现 10s+ 级退化。
- history 转换新增的内嵌 stream 展开成本在 p50 3–5ms、p95 < 25ms，未触发
  AGENTS.md 的“列表/history 同步工作”预警线。
- 流式中的 history 合并只在 translator 存在 live provisional 时追加一个条目，
  冷读路径不经过该分支。
